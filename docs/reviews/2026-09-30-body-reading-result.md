## 结论

可以作为一个独立 PR 提交。迁移、模型任务、分析输入、发布快照和后台操作共同解决“正文包含网页杂项，图中事实没有成为可复用正文”的问题，单独合并其中一层会缺少版本一致性。默认 `BODY_READING_MODE=off`，不自动重跑历史内容、不改行业评分门槛、不改变来源授权或用户认证。

审查后未保留阻止此默认关闭版本提交的 P0/P1 问题。生产切换 active 前，仍须完成真实模型的小样本人工核对；这属于启用条件，不能用本地测试桩代替。

## 自查中修复的关键问题

1. 对照模式任务在部署切换 active 后可能误激活：队列保留请求模式，shadow 的成功、失败及回执恢复均隔离。
2. 新文章重复执行发布可能提前展示未确认的原图：active 仅接受完整读取及对应分析，或继续保留此前完整发布。
3. 旧任务成功或失败可能影响新版本：源修订、读取代数和配置检查阻止旧结果激活；失败写回同样比较版本。
4. 人工修正可能保留未下载图片：保留图片必须有快照，新增版本和审计，不改历史结果。
5. RSS、X 卡片及页面可能仍使用源图或重复显示引用：使用发布快照；完整正文已包含的图/引用不在详情再次展示。
6. HTML 图注和 X 引用文字变化可能不构成修订：素材指纹包含正文结构、HTML 文字、图片及引用上下文，乱码保护保留。
7. 读取步骤未知付费回执释放后不能自动恢复：接入现有回执恢复，仍从读取阶段继续，shadow 不升级为发布。
8. 数据库备份缺少图片证据：文件备份加入 body-assets；保留策略明确不把证据当临时缓存。

## 保留的启用条件与实现边界

- 尚未调用线上配置的视觉模型，因此不能声称示例文章的价格、单位、日期已经被模型正确识别。先 shadow，逐图人工核对后再 active。
- 同 URL 更新由显式重读重新验证；没有新增全站定时图片下载器。历史文章按 ID/信源小批处理，最多 50 篇。
- 部分成功按图片保留；一张图的多个切片在同一批统一转录和校验，截断/缺项时重跑该批，未做切片级独立 OCR 拼接。
- 阅读任务采用自己的队列重试与租约，暂时复用文章的当前阶段尝试计数，读取成功进入分析时重置；逐图结果及回执保留。
- 证据历史暂不自动清理，需要共享持久卷、备份和容量监控。读取默认并发为 1。
- 归并单元格可以保存为安全 HTML 表格；Markdown 导出允许包含该 HTML，避免强行扁平化造成语义损失。

## 发布顺序

应用增量迁移 → 部署 API/worker/web（off）→ 核对共享数据卷与模型视觉能力 → 指定样本 shadow → 人工对照图片、摘要、Markdown → active → 按需小批处理历史。代码提交、远端分支、PR、服务器部署和线上文章回读分别确认，不互相替代。
